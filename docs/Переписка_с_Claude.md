### 1. Форма продукта

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Веб-приложение (PWA)** | Работают AI-диалог, режим преподавателя, аналитика, портфолио. Открывается на ПК, планшете и телефоне, можно поставить «как приложение». | Нужен сервер и сопровождение. |
| B. EPUB3 / PDF с интерактивом | Простой формат, работает офлайн. | Нет AI, аналитики и режима преподавателя. Это не закрывает задачи концепции. |
| C. Контент в H5P внутри Moodle или Canvas | Быстрый старт, если в вузе уже есть LMS. | AI-тьютор и ветвящиеся сценарии будут ограничены. |

**Рекомендация:** вариант A, плюс подключение к LMS вуза по протоколу **LTI 1.3**. Тогда студенты входят через привычную систему, а оценки уходят в журнал. Отдельные интерактивы можно делать в H5P и встраивать в книгу.

### 2. Технологии

- **Интерфейс:** React или Next.js, адаптивная вёрстка, PWA.
- **Сервер:** Python (FastAPI) или Node.js, база PostgreSQL.
- **Редактирование контента:** система управления контентом (Directus или Strapi). С ней методисты сами добавляют кейсы, задания и экспертные комментарии без программистов.
- **Ветвящиеся сценарии:** граф в формате JSON (узел → выбор → последствие) с визуальным редактором. Для прототипа подойдут Twine или Ink.
- **Видео:** потоковая передача (HLS) с собственного сервера, обязательно субтитры.
- **Поиск и фильтры:** встроенный поиск PostgreSQL или Meilisearch, теги по теме, сложности и типу ситуации.
- **Аналитика:** запись учебных событий в стандарте xAPI. Выгрузка в Excel/CSV и PDF-портфолио.

### 3. AI-ассистент (ядро проекта)

- **Модель:** большая языковая модель через API (Claude, GPT и др.) или своя открытая модель (Qwen, Llama, казахстанская KazLLM). Для своей модели серверу нужна видеокарта.
- **Режим тьютора, а не «решебника».** У каждого кейса есть скрытая от студента экспертная карта: ключевые проблемы, риски, применимые нормы и принципы, типичные ошибки, наводящие вопросы. AI сверяет с ней рассуждения студента и задаёт вопросы по шагам сценария: диагностика → решение → обоснование. Готовый ответ он не выдаёт.
- **Поиск по базе (RAG):** ассистент отвечает, опираясь на материалы теоретического навигатора, и ссылается на них.
- **Безопасность:** перед отправкой в модель текст очищается от персональных данных (ФИО, ИИН, телефоны); ответы помечены как сгенерированные AI; есть кнопка «Сообщить о некорректном ответе»; диалоги записываются для экспертной проверки.
- **Контроль качества:** 30–50 эталонных диалогов, на которых проверяется каждая новая версия подсказок или модели.

### 4. Схема данных кейса (основа для методистов)

У каждого кейса задаются поля: тема, сложность, тип ситуации, участники; описание или видео; вопросы для диагностики; варианты решений и их последствия (ветвление); экспертный комментарий; экспертная карта для AI; задания для рефлексии и критерии оценивания. Шаблон стоит утвердить на этапе 1: тогда контент и разработка пойдут параллельно.

### 5. Замечания к документу

1. **Итог бюджета не сходится.** Сумма разделов равна **25 185 000 т**, в документе указано 25 195 000 т (разница 10 000 т).
2. **Показатели противоречат друг другу.** Кейсов «не менее 3», а видеокейсов и комплектов по 45. В MVP формулировка «3 кейса по пяти темам» неоднозначна.
3. **Сервер не потянет свою языковую модель** — в нём нет видеокарты. Нужно либо использовать модель через API, либо добавить видеокарту уровня NVIDIA L40S или A100 (от примерно 5–8 млн т).
4. **Резервное копирование задублировано** (позиции 18 и 24).
5. **В бюджете нет расходов на сам продукт:** разработка, подписки на ПО, оплата AI-модели, видеопродакшн, домен, SSL-сертификат, работа юриста.
6. **Хранение персональных данных.** Закон РК о персональных данных требует хранить их на территории Казахстана. При использовании зарубежной AI-модели персональные данные нужно удалять до отправки. Стоит проверить с юристом.
7. **Язык интерфейса и контента** в концепции не указан.

### 6. Как выйти на пилот (MVP за 2–3 месяца)

1. Схема данных, 3–5 кейсов в шаблоне, сценарий одного видео.
2. Прототип: каталог кейсов → прохождение с ветвлением → AI-диалог → экспертный комментарий.
3. Режим преподавателя: выдача кейса группе, просмотр ответов, выгрузка.
4. Апробация на двух группах с формой обратной связи.

## 7. Схема авторизации

**Пользователь:**
Предложи схему авторизации в приложении e-book

**Claude:**
Свои пароли приложение не хранит. Студенты и преподаватели входят под университетской учётной записью, сам e-book работает через собственный сервер входа, а права определяются ролью.

### 1. Кто как входит

| Пользователь | Способ входа | Откуда аккаунт и группа |
|---|---|---|
| Студент | Университетская учётная запись или переход из LMS (LTI 1.3) | Группы — из Platonus |
| Преподаватель | Учётная запись + второй фактор | Роль и группы — из Platonus и каталога сотрудников |
| Методист, эксперт, администратор | Учётная запись + обязательный второй фактор | Роль назначает администратор |
| Внешний наставник | По приглашению преподавателя: ссылка на e-mail и одноразовый код | Доступ ограничен сроком |
| Гость | Без входа | — |

**Сервер входа** — Keycloak на собственном сервере (поз. 16): подключается к каталогу пользователей университета (Active Directory / LDAP) и к LMS, выдаёт приложению единый вход по OpenID Connect. **Platonus** — источник списков групп; нужно уточнить у IT университета, есть ли API или выгрузка.

### 2. Роли и права

| Роль | Что может |
|---|---|
| Гость | Каталог, описания кейсов, теоретический навигатор |
| Студент | Прохождение кейса, AI-диалог, портфолио, закладки, выгрузка своих результатов |
| Преподаватель | Назначение кейсов, ответы и аналитика **только своих групп**, оценивание |
| Методист / редактор | Создание и правка кейсов, экспертных карт, видео |
| Эксперт | Проверка кейсов, разбор жалоб на ответы AI |
| Администратор | Пользователи, роли, настройки; **без доступа к ответам студентов** |

AI-диалог доступен только после входа: запросы к AI стоят денег, диалоги журналируются, нужно согласие на обработку данных.

### 3. Как проходит вход

1. «Войти» или переход по ссылке из LMS.
2. Перенаправление на сервер входа: логин, пароль, при необходимости — код второго фактора.
3. Приложение получает подтверждение личности и подставляет роль и группы из Platonus.
4. При первом входе — согласие на обработку персональных данных (версия и дата сохраняются).
5. Сессия хранится в защищённой cookie, недоступной скриптам страницы.

### 4. Технические правила

- OpenID Connect с PKCE; ключи доступа живут 10–15 минут; сессия завершается после 8 ч бездействия.
- Временная блокировка после 5 неудачных попыток.
- Журнал действий (входы, смены ролей, просмотр ответов, выгрузки) хранится не менее года.
- AI-сервис получает только условный идентификатор вместо ФИО и ИИН.
- Выпускники и отчисленные теряют доступ при синхронизации с Platonus; перед удалением можно выгрузить портфолио.

### 5. Пилот и дальнейшее развитие

- **Пилот:** Keycloak + вход по университетской учётной записи + роли «студент / преподаватель / методист / администратор» + согласие при первом входе.
- **После апробации:** вход из LMS по LTI, синхронизация с Platonus, приглашения для наставников, роль эксперта, второй фактор для всех сотрудников.
