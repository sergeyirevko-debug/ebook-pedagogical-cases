# Сервис AI-тьютора `/api/tutor`

Сервис стоит между сайтом и `llama-server` с моделью **ebook-4B-v1** из комплекта `ebook-ai-tutor-bundle`. Его основа — эталон `server/tutor_server.py` из комплекта:

- промпт и формат карт перенесены без изменений;
- тест `tests/test_prompt_parity.py` сверяет их с эталоном побайтно на всех 117 картах.

Сверх эталона сервис делает то, что эталон упрощает (`docs/INTEGRATION.md` комплекта, п. 6).

```
Браузер ──/api/…──▶ nginx (443) ──▶ tutor.app :8000 ──▶ llama-server :8080 (ebook-4B-v1, CPU)
                                     │                 └▶ llama-server :8081 (e5-small, необязательно)
                                     └ SQLite: согласия, жалобы, диалоги (только по согласию)
```

Нужен Python 3.10+, только стандартная библиотека. Для входа через Keycloak (`AUTH_MODE=oidc`) дополнительно нужен PyJWT с cryptography (пакет `python3-jwt` в Ubuntu).

## Что зашито в модель — не менять

Модель обучена ровно на таком промпте. Без переобучения здесь ничего менять нельзя:

| Что | Где |
|---|---|
| Текст системного промпта | `data/system_prompt.txt`. При старте сервис сверяет его sha256 и откажется запускаться, если текст изменён |
| Формат `<материалы>`, включая оценки вариантов и служебные слова по-русски в обоих языках | `tutor/prompt.py` |
| Экспертный комментарий студенту не подаётся | `REFLECTION_ENABLED = False`. Включать только вместе с моделью v2 |
| Режим рассуждений выключен | `enable_thinking: false` в `tutor/llm.py` и `--reasoning off` у `llama-server` |
| Порядок сообщений | Системный промпт → материалы → история |

## Что добавлено к эталону

| Эталон | Здесь |
|---|---|
| Карты из JSON-файлов, включая 112 непроверенных | `tutor/cards.py`: модели подаются только **опубликованные** кейсы. Источник — выгрузка сайта (`tools/export_cases.mjs`), HTTP или Directus. Набор перечитывается каждые 5 минут; кейсы с ошибками в схеме отбрасываются |
| Без входа | `tutor/auth.py`: режимы `oidc` (Keycloak: JWT по JWKS, псевдоним = HMAC(sub)), `demo` (заголовки демо-входа прототипа) и `off` |
| Без лимитов | `tutor/limits.py`: лимиты на пользователя (6 в минуту, 200 в сутки) и очередь к слотам модели — при переполнении сразу 503 «занято». На nginx — щадящий лимит на IP |
| Регулярки ИИН, телефонов, e-mail | `tutor/pii.py`: плюс имена по словарю (`data/names.txt`, казахские и русские), фамилии и отчества по окончаниям. Не скрываются имена из текста текущего кейса («Арман*») и известные педагоги |
| Поиск по словам | `tutor/search.py`: плюс смысловой поиск на `multilingual-e5-small` через `llama-server --embeddings`. Если сервер векторов недоступен — снова по словам |
| `mode: teacher` по слову клиента | Экспертный комментарий получают только роли «преподаватель», «методист» и «эксперт» |
| Тексты не хранятся | `tutor/store.py`: ничего не пишется без согласия (`/api/consent`). Диалоги хранятся только при `STORE_DIALOGS=1`, 180 дней. Отзыв согласия удаляет диалоги. Жалобы уходят в очередь эксперта |
| — | Прогрев кэша префикса при старте и при смене набора карт. Журнал без текстов реплик: псевдоним, кейс, время ответа, статус |

## Эндпоинты

| Метод и путь | Что делает |
|---|---|
| `POST /api/tutor` | Контракт эталона: `{caseId, history, lang, mode?, stream?}` → `{reply, label, pii_redacted, suggest}`. При `stream: true` — SSE. Коды ошибок: 401/403 — вход и роль, 429 — лимит, 503 — модель занята, 502 — модель недоступна |
| `GET /api/tutor/health` | Состояние сервиса и модели, число опубликованных карт |
| `GET /api/tutor/cases` | Опубликованные кейсы, которые видит тьютор |
| `POST /api/tutor/report` | Жалоба «Сообщить о некорректном ответе»: контекст и ответ уходят эксперту |
| `GET /api/tutor/reports`, `POST /api/tutor/reports/<id>/resolve` | Очередь жалоб (роль «эксперт») |
| `POST /api/consent`, `DELETE /api/consent` | Согласие на обработку ПДн и его отзыв |

## Связь с сайтом (`src/app.js`)

- `askTutorLive()` отправляет запрос с `stream: true` и выводит ответ по мере генерации. Пока ответа нет, показывает «Думаю…».
- Если сервиса нет — страница открыта как файл, ответ 502 или 404, нет сети — сайт откатывается на прежний демо-режим (вопросы `c.ai[]`) с пометкой «AI временно недоступен».
- На 429 и 503 сайт показывает понятное сообщение.
- `suggest` превращается в кнопки кейсов. После 5 реплик по кейсу сайт предлагает «Сформулировать решение» и «Экспертный разбор».
- Жалобы уходят на сервер; кабинет эксперта читает их оттуда.
- Согласие с экрана входа передаётся на сервер, отзыв согласия — тоже.
- Адрес API: `/api/tutor`; для отладки его можно переопределить через `window.EBOOK_TUTOR_API`.

## Проверка

```bash
cd server
python3 -m unittest tests.test_api            # заглушка llama-server: поток, роли, ПДн, лимиты, очередь, 502, согласие, жалобы, OIDC
BUNDLE_DIR=../../ebook-ai-tutor-bundle python3 -m unittest tests.test_prompt_parity   # побайтно с эталоном
python3 tools/smoke.py --url http://127.0.0.1:8000                                     # с живой моделью
```

Локально на Windows — через llama-server (`server\run_local.ps1 -Llama <путь к llama-server.exe>`) или через Ollama (`server\run_local_ollama.ps1`). Скрипты запускаются из папки EBook командой `powershell -ExecutionPolicy Bypass -File …`; затем откройте http://127.0.0.1:8000/.

**Ollama.** Модель создаётся из GGUF комплекта по `ollama/Modelfile`. Сервис включает этот режим переменными `LLM_KIND=ollama`, `LLM_URL=http://127.0.0.1:11434`, `LLM_MODEL=ebook-4b`.

Ollama 0.34 применяет к Qwen3.5 собственный шаблон из GGUF и разбор «рассуждений». В итоге ответ уходил в поле `reasoning`, а модель начинала рассуждать вслух. Поэтому сервис сам собирает промпт ровно как `chat_template.jinja` модели при `enable_thinking=false` и отправляет его в `/api/generate` с `raw: true`. Совпадение с шаблоном проверяет `tests/test_ollama_prompt.py` на всех кейсах. Параметры генерации передаются в `options`. Модель держится в памяти 30 минут после последнего запроса.

Для сервера университета основной вариант — llama-server: модель тестировалась именно на нём.

Развёртывание на сервере ВКУ описано в `deploy/` и в документе «План развёртывания AI-тьютора».
