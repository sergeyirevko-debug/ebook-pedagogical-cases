# E-book «Банк педагогических ситуаций» — прототип

Кликабельный двуязычный (қазақша / русский) прототип по макету UI.
Открыть: двойной щелчок по `index.html` — работает в браузере без сервера и интернета.

## Что есть

| Экран | Маршрут | Что демонстрирует |
|---|---|---|

### Авторизация (демо)

Вход только по собственным учётным записям e-book — сторонние сервисы (SSO, Platonus, LMS) не используются.
Гость видит каталог, описания кейсов, видео и методматериалы. Анализ, решения, AI-диалог и портфолио — после входа.

- Вход: e-mail + пароль. Демо-адреса: `student@ebook.demo`, `teacher@ebook.demo`, `methodist@ebook.demo`, `expert@ebook.demo`, `admin@ebook.demo`, `mentor@ebook.demo` (пароль любой) или кнопки быстрого входа.
- 5 неудачных попыток — блокировка входа (в рабочей системе на 15 минут).
- Активация: код из приглашения или от преподавателя (демо: `STUD-2026`, `MENT-2026`) → свой пароль (≥10 символов, буквы и цифры).
- Сотрудникам (преподаватель, методист, эксперт, администратор) — второй фактор, код из приложения-аутентификатора (демо: любые 6 цифр).
- Восстановление пароля — ссылка на e-mail; без почты — новый код активации от преподавателя.
- Преподаватель импортирует список группы и выдаёт коды активации («Режим преподавателя»).
- При первом входе — согласие на обработку персональных данных. Права ролей — объект `PERMS` в `src/auth.js`.

Переключатель **ҚАЗ / РУС** в шапке, выбор запоминается. Заметки, решения и рефлексия сохраняются в браузере (localStorage).

## Структура

```
src/i18n.js   — строки интерфейса {ru, kz}
src/data.js   — категории, принципы, 5 демо-кейсов по единой схеме
src/auth.js   — роли, права, экраны входа, кабинеты методиста, эксперта, администратора
src/app.js    — роутер, экраны, демо AI-тьютор
src/style.css — стили (адаптив: ПК / планшет / смартфон с нижним меню)
assets/logo.png — логотип университета (встраивается в index.html при сборке)
build.py      — собирает всё в index.html:  python build.py
server/       — сервис AI-тьютора /api/tutor (Python, без зависимостей) + развёртывание (server/deploy)
```

## Схема кейса (для методистов)

`id, cats[], grade, level, title{ru,kz}, text{ru,kz}, options[{ru,kz,oc,cons{ru,kz}}], expert{ru,kz}, principles[], ai[{ru,kz}]`

`ai[]` — «экспертная карта» для AI: наводящие вопросы, которые тьютор задаёт по шагам.

## Что заменить при переходе к продакшену

- ~~`askTutor()` → `POST /api/tutor`~~ — **сделано**: чат вызывает сервис AI-тьютора (`server/`, модель ebook-4B-v1 через llama.cpp) с потоковым выводом; без сервиса — прежний демо-режим. См. `server/README.md`.
- `data.js` → API системы управления контентом (Directus / Strapi).
- Демо-вход (`src/auth.js`) → собственный сервер авторизации без внешних зависимостей (Keycloak в автономном режиме или встроенная авторизация бэкенда): хеши паролей Argon2id, TOTP для сотрудников, письма через SMTP университета, сессия в httpOnly-cookie.
- localStorage → БД PostgreSQL; журнал действий и жалобы на AI — на сервере.
- Заглушки видео → HLS-плеер с субтитрами kz/ru.
